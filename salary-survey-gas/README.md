# 2025 年環安衛薪資調查系統

取代原本的 Google 表單，改為自建的線上問卷 + 薪資百分位回饋 + 自動分析報告 + 系統後台。

| 項目 | 內容 |
|---|---|
| 調查期間 | 民國 115/10/09 ～ 115/11/08（西元 2026-10-09 ～ 2026-11-08） |
| 薪資年度 | 2025 年度（原表單的「111 年度」已全面改為 2025） |
| 抽獎 | 從填 Email 者抽 5 位，各致贈 500 元禮券；留 Email 者另寄完整統計報告 |
| 百分位門檻 | 有效樣本達 **30 份**才對外顯示統計數字 |
| 後端 | Google Apps Script Web App + Google 試算表 |

## 部署步驟

1. 推送程式碼（`.clasp.json` 的 `scriptId` 已填好）
   ```
   cd salary-survey-gas
   clasp push
   ```
2. 開啟 Apps Script 編輯器，**手動執行一次 `initSystem()`**（會跳出授權，要按同意）
   - 綁定式專案（從試算表 → 擴充功能 → Apps Script 建的）：直接用那份試算表
   - 獨立式專案：會自動在雲端硬碟建一份「職安人員薪資調查 — 資料庫」，
     ID 存進 Script Properties，**執行紀錄會印出試算表網址**
   - 想改用現有的試算表：執行 `setSpreadsheetId('<試算表ID>')`

   完成後會有 `回覆資料`／`抽獎名單`／`系統設定`／`操作日誌` 四張工作表。
3. **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我**
   - 具有存取權的使用者：**所有人**
4. 取得 `/exec` 網址，這就是要發出去的問卷連結
5. 之後更新程式：
   ```
   clasp push
   clasp deploy -i <部署ID>
   ```
   （用 `-i` 更新既有部署，網址不會變）

### 系統後台

密碼存在 Script Properties 的 `ADMIN_PW`（預設 `b7710182`），在**伺服器端比對**，不會寫進網頁原始碼。
要換密碼，在編輯器執行 `setAdminPassword('新密碼')`。

> 後台能一鍵清空全部資料。密碼只擋得住誤觸，擋不住有心人，若網址外流建議換成更長的密碼。

進出方式：問卷首頁右上角的**齒輪**開新分頁進後台；後台右上角的**「回到問卷系統」**回去。

後台功能：

| 功能 | 說明 |
|---|---|
| 資料概況 | 回覆筆數、有效樣本、異常值、抽獎名單、操作日誌，以及是否已達 30 份 |
| 隨機抽獎 | 從抽獎名單隨機抽 N 位，顯示 Email／電話／地址；沒填地址者自動標註寄電子禮券 |
| 新回覆通知信 | 每收到一筆就寄信通知；可改收件信箱、寄測試信，並選擇是否附上薪資數字 |
| 異常值審核 | 列出被規則判為異常的每一筆（原因、月薪、年終、年收、加班、分類），可勾選「計入統計」逐筆放行；`recalcDerivedColumns()` 不會覆蓋人工決定 |
| 最近的回覆 | 列出最近 50 筆，可**單筆刪除**測試資料 |
| 匯入 2023 年調查資料 | 從舊調查隨機抽樣匯入，或整批移除已匯入的資料 |
| 正式發布前的清除 | 分別或一次清空「問卷回覆／抽獎名單／操作日誌」，每次都要輸入確認文字 |
| 重算衍生欄位 | 改過分組規則後重算區域、年資級距、異常值 |

### 寄信額度

Apps Script 的限制是**每天**算的，沒有月上限：一般 Gmail 帳號 **100 封／天**，
Workspace 付費版 1,500 封／天。剩餘額度低於 5 封時自動略過寄信，只記進操作日誌。

> 調查結束要把報告寄給所有留 Email 的人時才是真正吃額度的地方。
> 若有 300 人留信箱，一天 100 封得分三天寄完，屆時需要加一個分批寄送的排程。

### 新回覆通知信

**通知節奏會自動切換**，由 `程式碼.js` 最上面的 `NOTIFY_EACH_UNTIL` 決定：

| 日期 | 行為 |
|---|---|
| `NOTIFY_EACH_UNTIL`（含）以前 | 每一筆回覆寄一封 |
| 之後 | 改成**每週日 9 點**寄一份摘要（`sendWeeklyDigest`，由時間觸發器執行） |

目前設定 `2026-10-09`，也就是 10/09 當天逐筆寄、10/10 起改週報。要延長逐筆模式就把日期往後改。

週報內容只有彙總數字：本週新增、累計、距離 30 份門檻、本週行業與年資分布，
樣本達標後再附累計中位數。**不列任何單筆回覆**——理由同下。

設定存在 Script Properties：`NOTIFY_ON`（預設開）、`NOTIFY_EMAIL`、`NOTIFY_DETAIL`（預設關）。
寄信失敗只寫進操作日誌，**絕不影響問卷送出**。
觸發器由 `authorizeAll` 或後台的「重設週日排程」安裝，重複安裝不會累加。

> **第一次使用要先授權。** `MailApp` 是後來才加的，既有的授權不含寄信權限，
> 通知信會失敗。`appsscript.json` 已明確宣告需要的 OAuth 範圍，
> 到 Apps Script 編輯器執行 **`authorizeAll`**（在 `程式碼.js` 最上面，打開編輯器預設就選到它），
> 同意畫面會一次把權限要齊，並寄一封確認信給你。執行紀錄會逐項列出檢查結果。
>
> 授權畫面如果出現「Google 尚未驗證這個應用程式」，點「進階」→「前往（不安全）」——
> 這是你自己的指令碼，沒有上架驗證才會這樣提示。
>
> 授權完成後記得再 `clasp deploy -i <部署ID>` 一次，正式網址才會跟著更新。

**通知信預設不含薪資數字**，這是刻意的：通知信有精確到秒的時間，抽獎名單卻只記到「日」
又是亂序插入——正是為了讓兩者對不起來。如果通知信附上薪資，管理者只要在收到信的當下
去看抽獎名單多了哪一列，就能把 Email 和薪資配起來，推翻問卷頁對填答者的承諾。
後台有開關可以打開，但打開就等於放棄那個保證。

## 隱私設計：聯絡資訊為什麼不會洩漏薪資

送出問卷時，系統把資料拆成兩條完全獨立的路徑：

| | 工作表 A `回覆資料` | 工作表 B `抽獎名單` |
|---|---|---|
| 主鍵 | `R` + 12 碼隨機亂碼 | `D` + 10 碼隨機亂碼（**另一組**） |
| 內容 | 年齡、年資、行業、薪資…（56 欄） | 只有 Email／電話／地址（5 欄） |
| 時間 | 完整時間戳 | **只到日，不記時分秒** |
| 寫入順序 | 依序 append | **隨機插入列**，不按送出順序 |

兩張表之間**沒有任何共同欄位**，連寫入順序與時間都刻意打亂，因此管理者也無法把某個 Email 對回某一筆薪資。

問卷頁的「看後台實際長什麼樣」可展開**後台兩張工作表的畫面重現**（真實欄位名、Google Sheets 的列號與分頁樣式）—— 讓填答者一眼看到「A 表沒有 Email 欄、B 表沒有薪資欄」，比文字保證有說服力。

`回覆資料` 只有一個 `joined_draw` 欄位記錄「有沒有參加抽獎」，不含聯絡資訊本身。

### 聯絡資訊欄位

Email、電話、地址**全部選填**。規則：

- 只填電話或地址、沒填 Email → 後端擋下（無法通知中獎）
- 填了 Email 但沒填地址 → 中獎時**只寄電子禮券到 Email**，結果頁與問卷頁都會先講明
- 電話只在 Email 聯絡不上時使用
- `drawWinners()` 抽出名單時，沒填地址者會自動標註「未填地址 → 寄電子禮券到 Email」
- 留了 Email 的人，**統計結束後會收到完整統計報告**（問卷頁與結果頁都有說明）

### 中英雙語

**開場提示視窗最上方就是語言選擇**（中文 / English），進站第一件事就能選。
頁首右上角另有一組切換鈕供中途改變主意用。選擇記在 `localStorage`，下次開啟沿用。
頁首的標題與 tagline **中英並列**，不用切也看得懂這是什麼調查。

**關鍵設計：選項的「值」永遠是中文，原樣寫進試算表，只有顯示文字會翻譯。**
所以切成英文填答的資料，跟中文填答的會落在同一個統計分組，不會把報告切成兩半。

字典在 `i18n.html`，key 就是畫面上的中文原字串：

```js
var DICT = { '請問您的年齡':'Your age', '營造業':'Construction', ... };
```

新增中文字串時，用 `T('…')` 包起來並在 `i18n.html` 補一條就好。
`scratchpad/i18ncheck.js` 會把六個步驟都渲染一次，列出所有漏翻的中文。

### 國際職安證照

獨立一題（`intl_licenses`），**不併入「國內證照最高等級」的分組**，避免打亂原有的
甲級／乙級／業務主管排序。報告中另有「依國際職安證照分類」的薪資比較與明細分布。

收錄：NEBOSH IGC（Level 3）／International Diploma（Level 6）／PSM／Environmental、
IOSH Managing Safely 與會員資格、OSHA 10/30-hour、BCSP CSP／ASP、ABIH CIH、
ISO 45001 主導稽核員、IEMA，另有「其他」自填欄。

### 必填範圍

**報告會用到的分組與統計欄位一律必填**，只有純補充性質的才是選填。

必填：年齡、性別、學歷、科系領域、職安證照、其他證照、專業能力、語言能力、
三項年資、現職分類、產業細分、職稱職級、是否專責、是否有部屬、公司規模、工作地、
工作內容、工作型態、加班時數、加班費給付、月全薪、年總獎金、全年收入、調薪幅度、福利、
前一份工作、薪水變化、滿意度、轉職打算。

選填：檢定種類與分數、薪資變化幅度、特休天數、建議、Email／電話／地址。

為了讓「沒有」也能被統計，其他證照與專業能力都加了「以上皆無」選項，
語言能力有「0 分 無／未測驗」，加班時數與年總獎金可填 0。

### 自動帶入與連動

- **職安工作年資**：營造業＋廠工安＋其他三欄自動加總，即時顯示總年資與統計分組
- **全年本業總收入**：月全薪 × 12 ＋ 年總獎金 ＋ 加班費自動帶出（唯讀），下方列出組成明細，
  可勾選改為手動填寫
- **加班費**：以平日每小時工資額（月全薪 ÷ 240）× 1.5 倍 × 每月加班時數 × 12 估算。
  給付方式為「折換補休」「責任制／不給付」「定額加班費（包月）」時不計入現金
  （補休沒有現金、包月已含在月全薪裡），畫面會標明原因與 ＋0。
  因此「月全薪」的定義改成**不含加班費**，避免重複計算。
- **前一份工作選「應屆畢業」或「同樣是職安工作」**：薪水變化一題自動帶「不適用」並隱藏

薪資異常值與加班異常值**分開判定**：加班時數填得離譜只會排除於加班統計，該筆的薪資資料仍然有效。

## 分析報告內容

對齊原本那份《非正式職安薪資調查報告》的骨架，並多給 P25／P75：

1. **封面**：調查期間、有效樣本、排除筆數、薪資年度、備註
2. **整體資料分析**：學歷、職安證照（最高等級）、其他證照、其他專業、外語能力、職安專責、工作經驗、職業分類、工作區域、年齡、公司規模、職級、工作型態、加班費給付、調薪、轉職意願 → 人數／比例／橫條
3. **複選題分布**：工作內容、專業能力、其他證照、福利
4. **薪資分析**：整體 ＋ 依學歷／工作經驗／職安證照／外語能力／其他證照／工作區域／現職分類／公司規模／職級／年齡，每組「月薪・年終・總薪水 × 最小／最大／平均／中位數／P25／P75」
5. **分析報告**：八大主題自動產生文字結論（只納入 n ≥ 5 的組別，比較中位數）

按「列印／另存 PDF」即可輸出成跟原報告一樣的 PDF。

## 管理功能（在 Apps Script 編輯器手動執行）

| 函式 | 用途 |
|---|---|
| `initSystem()` | 建立工作表（部署後執行一次） |
| `drawWinners()` | 從抽獎名單隨機抽 5 位，結果印在執行紀錄 |
| `recalcDerivedColumns()` | 改過分組規則（區域、年資級距、異常值門檻）後重算全部衍生欄位 |
| `clearStatsCache()` | 清除報告快取（統計預設快取 120 秒） |

### 可調參數（`程式碼.js` 最上方）

```js
const SURVEY_START = '2026-10-09';   // 115/10/09
const SURVEY_END   = '2026-11-08';   // 115/11/08
const SURVEY_YEAR  = 2025;
const DRAW_WINNERS = 5;
const DRAW_PRIZE   = '500 元禮券';

const OUTLIER = {
  monthlyMin: 20000,  monthlyMax: 500000,
  annualMin: 200000,  annualMax: 10000000,
  otMax: 300
};
```

調查期間以這兩個常數為準：未開始或已結束時，問卷頁會自動換成說明頁並導向分析報告。
